# Система генерації та оцінки складності рівнів (Level Design Logic)

Цей документ описує математичну модель, алгоритми та поточний стан системи автоматизованого створення рівнів гри "Color Rings".

## 1. Поточний стан (Current Status)
Реалізовано розширену систему генерації та менеджменту рівнів:
*   **LevelState.cs**: Математична модель (матриця кольорів). Підтримує "атомарні ходи" — будь-яке зміщення на будь-яку відстань рахується як 1 хід.
*   **LevelSolver.cs**: Вдосконалений алгоритм **A* (A-Star)**. Знаходить найкоротший шлях, враховуючи жорсткі обмеження (Blocked, FilterColors).
*   **LevelGenerator.cs**: Розумний генератор з підтримкою цільової складності (`Target Difficulty`). Робить до 10 спроб знайти оптимальний рівень.
*   **LevelGeneratorWindow.cs**: Повноцінний Level Manager.
    *   **Налаштування**: Рандомізація смуг, секторів, арен, шансів блокування, фільтрів та пустих сегментів.
    *   **Прев'ю**: Лінійне відображення смуг (stripes) з прямокутними сегментами, вертикальними смугами арен та індикаторами статусів.
    *   **Браузер**: Список усіх рівнів у проекті з можливістю швидкого перегляду та завантаження.
    *   **Збереження**: Автоматичне збереження розрахованої складності в `.asset` та підтримка власних назв файлів.

## 2. Алгоритм та метрики ходів

### Визначення "Одного Ходу"
Для покращення геймплею та чесної оцінки складності прийнято наступну метрику:
*   **Rotate**: Поворот однієї смуги на будь-яку кількість позицій одним рухом = **1 хід**.
*   **Slide**: Переміщення сегментів по вертикалі в межах однієї слайд-арени на будь-яку відстань = **1 хід**.
*   **Валідація**: Ходи, що не змінюють стан матриці (наприклад, поворот одноколірної смуги), не враховуються і не вважаються ходами.

### Solver (A* Engine)
*   **Евристика**: Сума відсутніх сегментів до повного заповнення кожної смуги домінуючим у ній кольором.
*   **Правило Blocked**: Якщо в смузі є заблокований сегмент, вся смуга не може обертатися. Слайд-арена блокується, якщо на її шляху є Blocked сегмент.
*   **Правило FilterColors**: Арена дозволяє слайд лише в тому випадку, якщо **всі** сегменти в результаті переміщення відповідають списку дозволених кольорів цієї арени.

## 3. Реалізовані обмеження та правила (Constraints)
1.  **Ring Span**: Арени можуть охоплювати не всі смуги, а лише заданий діапазон (наприклад, тільки 2 центральних смуги).
2.  **Adjacency Rule**: Арени в сусідніх секторах не можуть мати спільних смуг (повна ізоляція по вертикалі для сусідніх секторів).
3.  **Uniqueness Rule**: Не допускається використання ідентичних за діапазоном смуг слайд-арен (наприклад, не може бути двох арен 1-2 у різних секторах).
4.  **Solver Safety**: Асинхронна робота з можливістю миттєвої зупинки (`CancellationToken`).

## 4. Pre-Game Placement (Розміщення сегментів)

### Призначення
Механіка попереднього розміщення сегментів, що дозволяє гравцю заповнити пусті слоти перед початком основного геймплею.

### Сегменти зі статусом Empty
*   `SegmentStatus.Empty = 4` — новий статус для порожніх слотів.
*   Відображаються сірим кольором `(0.5, 0.5, 0.5, 0.6)` з пунктирною рамкою в прев'ю.
*   Мають сіру квадратну статус-іконку в грі.

### Генерація з Empty сегментами (інтелектуальний вибір)
Параметри в `LevelGenerator.GenerationParams`:
*   `AllowEmptySegments` (bool) — увімкнення фічі
*   `MinEmptySegments`, `MaxEmptySegments` (int) — діапазон кількості Empty сегментів
*   `UseIntelligentEmpty` (bool) — увімкнення інтелектуального вибору
*   `EmptyMinScore` (float 0-10) — мінімальний поріг балу для кандидата
*   `EmptyTopKForSolver` (int) — кількість топ-кандидатів для перевірки через солвер

#### Система оцінки (EmptySegmentScorer)
Кожен кандидат отримує бал 0-10 за 5 факторами:

| Фактор | Макс. бал | Опис |
|--------|-----------|------|
| **Неоднозначність кольору** | 3 | Скільки інших сегментів того ж кольору в стріпі |
| **Частота кольору** | 2 | Якщо колір домінує — більша неоднозначність при видаленні |
| **Участь в слайд-арені** | 2 | Сегмент в арені = додаткова складність |
| **Порушник патерну** | -1 / +2 | Єдиний інший колір = мінус (підказка). Частий = плюс |
| **Позиція в стріпі** | 1 | Центральні позиції складніше для вгадування |

#### Гібридний підхід (UseIntelligentEmpty = true)
1. Евристика присвоює кожному кандидату базовий бал
2. Топ-K кандидатів перевіряються через A* солвер
3. Фінальний бал = евристика × 0.4 + солвер × 0.6
4. Обираються N кандидатів з найвищим балом (бал >= поріг)

#### Рівні складності
*   **Легкий (1-5)**: 1-2 Empty, низький поріг балу (0-3)
*   **Середній (6-10)**: 2-4 Empty, середній поріг (4-6)
*   **Складний (11+)**: 3-5 Empty, високий поріг (7-10)

### Архітектура PreGamePlacementModule
*   `IPreGamePlacementService` — інтерфейс сервісу
*   `PreGamePlacementService` — основна логіка (вибір, розміщення, анімація)
*   Модуль не залежить від `StripRotationService` та `SlideSegmentService`

### Flow розміщення
1. Рівень ініціалізується повністю (спавн смуг, арен, тощо)
2. `LevelStarted()` викликається, `InputBlocked = false`
3. `StartPlacement().Forget()` запускається окремо (не блокує ініціалізацію)
4. Якщо є Empty слоти → `InputBlocked = true`
5. Гравець заповнює всі слоти → `InputBlocked = false` → геймплей активний

### Взаємодія
1. **Вибір сегмента з пулу** → `ZoomIn(true)` на сегменті, `ZoomIn(true)` на всіх Empty слотах
2. **Тап на Empty слот** → анімація польоту (0.35с, ease-out cubic) → сегмент стає кольоровим
3. **Тап поза слотами** → скасування вибору
4. **Вибір іншого сегмента** → попередній вибір замінюється

### Візуалізація в прев'ю
*   **Empty**: Сіре заповнення + пунктирна рамка
*   **Blocked**: Чорна крапка по центру
*   **Default**: Кольоровий прямокутник
*   **Слайд арени**: Вертикальні білі смуги по центру сегментів
