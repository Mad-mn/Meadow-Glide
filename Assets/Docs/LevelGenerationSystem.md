# Система генерації та оцінки складності рівнів (Level Design Logic)

Цей документ описує математичну модель та алгоритми для створення рівнів гри "Color Rings".

## 1. Загальна концепція механіки
Гра базується на маніпуляції сегментами в полярній системі координат.
*   **Кільця (Rings):** Концентричні кола, кожне з яких може обертатися незалежно.
*   **Сегменти (Segments):** Кольорові елементи всередині кілець. Мета — зібрати всі сегменти одного кольору в межах одного кільця.
*   **Слайд-Арени (Slide Areas):** Фіксовані сектори, через які сегменти можуть переміщатися між кільцями (вертикальний зсув).

## 2. Параметри варіативності (Переменні складності)
Для створення унікальних рівнів використовуються наступні параметри:
1.  **Кількість кілець:** Від 2 до 8+.
2.  **Кількість сегментів на кільце:** Може бути однаковою для всіх або різною (що створює геометричні обмеження для слайду).
3.  **Кількість слайд-арен:** Чим більше арен, тим більше варіантів ходів.
4.  **Діапазон слайду (Circle Indices):** Обмеження слайду конкретними кільцями (наприклад, арена тільки між 1-м та 2-м кільцем). Це ключовий фактор складності.
5.  **Початковий "заміс" (Scramble):** Кількість та логіка випадкових ходів від зібраного стану.

## 3. Математична модель (Solver)
Для автоматичного прорахунку складності використовується алгоритм пошуку шляху (BFS або A*).

### Представлення стану (State)
Стан гри описується матрицею `int[RingCount][SegmentCount]`, де значення — це ID кольору.

### Валідні ходи (Moves)
*   **Rotate(ringIndex, direction):** Зсув масиву кольорів у кільці на 1 крок.
*   **Slide(areaIndex, direction):** Зсув кольорів між кільцями в конкретному секторі (індексі сегмента), визначеному ареною.

### Оцінка складності (Difficulty Metrics)
1.  **God's Number:** Мінімальна кількість ходів для вирішення з поточного стану.
    *   *Легкий:* 3–6 ходів.
    *   *Середній:* 7–12 ходів.
    *   *Складний:* 13–20+ ходів.
2.  **Branching Factor:** Середня кількість доступних унікальних ходів.
3.  **Interconnectivity:** Показник того, наскільки часто слайд-арени перетинаються або використовують одні й ті самі кільця.

## 4. Алгоритм генератора рівнів
Генерація відбувається методом "Reverse Scramble":
1.  **Initialize:** Створення ідеально зібраного стану (кожен масив кільця заповнений одним кольором).
2.  **Randomize Config:** Випадковий вибір кількості арен, їх розташування та діапазону (indices).
3.  **Scramble:** Виконання $N$ випадкових ходів.
4.  **Solve:** Запуск Solver для пошуку найкоротшого шляху.
5.  **Output:** Якщо найкоротший шлях відповідає цільовій складності, конфіг зберігається як `LevelConfig.asset`.

*   [ ] **GameSolver.cs:** Реалізувати C#-клас, який зможе симулювати ходи без візуалізації та знаходити рішення.
