# Game Design Document: Color Rings

---

## 1. Ігровий цикл (Core Gameplay Loop)

**Основний цикл:**
```
Отримати рівень → Заповнити пусті слоти (якщо є) → Обертати/слайдити сегменти → 
Зробити всі смуги одноколірними → Виграти / Вичерпати ходи → Програти
```

**Гравець отримує:**
- Сітку горизонтальних смуг (stripes), кожна з N сегментів різних кольорів
- Слайд-арени — вертикальні зони, де можна переміщувати сегменти між смугами
- Обмежену кількість ходів

**Два типи дій:**
1. **Обертання (Rotate)** — горизонтальне зміщення всіх сегментів у смузі. Один рух = один хід.
2. **Слайд (Slide)** — вертикальне переміщення стовпчика сегментів через слайд-арену. Один рух = один хід.

**Умова перемоги:** Всі сегменти в кожній смузі мають бути одного кольору (IsCompleted).

**Умова поразки:** Ходи вичерпані, але не всі смуги заповнені.

## 2. Існуючі ігрові механіки

| Механіка | Опис | Складність |
|----------|------|-----------|
| **Rotate** | Горизонтальне прокручування сегментів у смузі | Базова |
| **Slide** | Вертикальне переміщення між смугами через арени | Базова |
| **Blocked segments** | Сегменти, що не можуть бути переміщені (обмежують слайд) | Помірна |
| **FilterColors** | Арена дозволяє слайд лише певних кольорів | Помірна |
| **Empty segments (Pre-game)** | Пусті слоти, які гравець заповнює перед грою з пулу | Помірна |
| **Tutorial** | Базова система підказок (але `IsTutorialCompleted` завжди `false`) | Мінімальна |

## 3. Пул рівнів та обсяг контенту

- **newBalance:** 50 рівнів (з різною складністю)
- **GeneratedLevels:** 19 рівнів (згенеровані через A* солвер)
- **Загалом:** ~69 рівнів
- **Час проходження:** ~1-2 хвилини на рівень → **~70-140 хвилин** = **1.2-2.3 години**
- **Складність:** Визначається формулою `MovesForLevel = Difficulty × DifficultyMultiplier (2.0)`
- **Параметри, що варіюються:** Кількість смуг, кількість секторів, кількість арен, кількість кольорів (до 6), Blocked, FilterColors, Empty

---

## 4. Система прогресії

**Поточна прогресія:**
- Лінійна: Level 1 → Level 2 → Level 3 → ...
- `PlayerProgressData` зберігає лише поточний номер рівня (`int Level = 1`)
- Немає картки рівнів, глав, або візуальної прогресії
- Немає рейтингу (зірки, бали)
- Немає прив'язки до соціальних мереж

## 7. Аналіз ризиків для утримання (Retention)

**Ризик 1: "Механіка занадто швидко стає зрозумілою"**
- Гра має лише 2 типи дій (rotate + slide). Після 10-15 рівнів гравець повністю розуміє всі комбінації.
- **Наслідок:** D7 retention може бути низьким, якщо немає елементів, що ускладнюють/змінюють досвід.
- **Рекомендація:** Потрібні нові механіки або зміна правил з часом (unlock нових механік).

**Ризик 2: "Немає мети окрім 'пройти наступний рівень'"**
- Прогресія — просто номер рівня. Немає візуальної карти, зірок, досягнень.
- Гравець не бачить свого прогресу.
- **Наслідок:** Мотивація "відкрити наступне" слабка.

**Ризик 3: "Немає причин повертатися щодня"**
- Немає daily rewards, daily challenges, streaks.
- Гравець може пройти все за один сеанс і ніколи не повернутися.

**Ризик 4: "Поразка відчувається несправедливо"**
- Коли ходи закінчуються — просто LoseView. Немає хінтів, немає можливості відкрутити хід.
- +5 ходів без обмежень — занадто щедро, знецінює складність.

**Ризик 5: "Немає аналітики — не можна приймати рішення"**
- Без analytics не можна зрозуміти, на яких рівнях гравці застрягають, де кидають гру, які механіки працюють.

## 9. Технічні обмеження

- Поточний save system (BinaryFormatter) не працює на IL2CPP/WebGL — потрібна міграція на JSON
- Tutorial не працює (`IsTutorialCompleted` завжди `false`) — гравець може не зрозуміти механіки
- Debug панель доступна — може бути випадково відкрита в релізі
- Level generator може генерувати нерозв'язні рівні — потрібна валідація solver перед релізом
- Pre-game placement може бути незрозумілим — гравець може не зрозуміти, що потрібно робити
- Одноманітність візуалу — всі рівні виглядають однаково (горизонтальні смуги). Потрібні теми/скіни
