# Plan: Improve Level Difficulty Calculation + Fix Blocked Segments Bug

## Problem 1: Difficulty = shortest path is not enough

Currently `difficulty = solver.Solve()` returns just the A* shortest path length. A level with 8 moves on 3 rings is much easier than 8 moves on 6 rings because:
- More rings = more possible wrong rotations
- More sectors = more rotation offsets to consider
- Wider slide areas = more complex interactions

**Solution: Composite metric with 3 factors**

```
Difficulty = PathLength × (1 + avgConfusion + avgPlanningDepth)
```

**Factor 1: PathLength** — A* solution steps (existing metric)

**Factor 2: avgConfusion** — average ratio of non-productive moves to total moves along the solution path.
- For each state along the solution path, enumerate all valid moves
- Count moves that do NOT reduce the heuristic (don't get closer to solution)
- `confusion = nonProductiveMoves / totalMoves` at each step, averaged across all steps
- Captures: how many "traps" exist at each decision point

**Factor 3: avgPlanningDepth** — cognitive load from slide area span.
- For each slide area: `log2(span)` where span = number of rings it covers
- Normalized to [0, 1] by dividing by `log2(maxRings)`
- Averaged across all areas
- Captures: wider areas (3+ rings) require more planning — player must think "where will each segment go" before sliding

**Why this works:**
- Monotonic: more steps + more confusion + wider areas = always harder
- Captures the ring-count effect (more rings = more confusion)
- Captures the span effect (wider areas = more planning)
- Simple to understand and tune
- Backward-compatible: `LevelConfig._difficulty` stays `int`

**Example:**
- Level A: 8 steps, confusion=0.3, planningDepth=0.3 → Difficulty = 8 × 1.6 = 13
- Level B: 8 steps, confusion=0.53, planningDepth=0.63 → Difficulty = 8 × 2.16 = 17

Level B is genuinely harder: same path length, but more wrong moves and wider areas requiring more planning.

## Problem 2: Blocked segments create unsolvable levels

When generating with blocked segments, the generator may place blocked segments of the same color on DIFFERENT rings. Since blocked segments can't be moved between rings (slide is blocked), the level becomes unsolvable — you can't gather same-color segments onto one ring.

**Root cause**: After scramble, the generator only validates `IsSolved()` (line 171), not solvability. The initial state might be solvable, but scramble moves blocked segments to impossible positions.

**Solution**: After scramble, re-solve to verify solvability. If `solver.Solve()` returns -1, discard and retry.
