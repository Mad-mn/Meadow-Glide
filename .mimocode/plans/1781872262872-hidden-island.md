# Fix: 2★ threshold too close to 3★

## Problem

`SolveAll` finds near-optimal solutions, so `averageMoves ≈ shortest + 1`. Gap of 1 move between 3★ and 2★ is too small.

## Solution

Replace `averageMoves` calculation with confusion-based formula:

```
averageMoves = shortest + (maxMoves - shortest) * (0.3 + confusion * 0.4)
```

Examples for shortest=8, max=16:
- confusion=0.2 → averageMoves = 8 + 8 * 0.38 = 11
- confusion=0.4 → averageMoves = 8 + 8 * 0.46 = 12
- confusion=0.6 → averageMoves = 8 + 8 * 0.54 = 12
- confusion=0.8 → averageMoves = 8 + 8 * 0.62 = 13
