# Game Design Analysis: Color Rings — Soft Launch Readiness

---

## ЧАСТИНА 1: АНАЛІЗ ПОТОЧНОГО СТАНУ ГРИ

### 1.1 Ігровий цикл (Core Gameplay Loop)

**Основний цикл:**
```
Отримати рівень → Заповнити пусті слоти (якщо є) → Обертати/слайдити сегменти → 
Зробити всі смуги одноколірними → Виграти / Вичерпати ходи → Програти
```

**Гравець отримує:**
- Сітку горизонтальних смуг (stripes), кожна з N сегментів різних кольорів
- Слайд-арени — вертикальні зони, де можна переміщувати сегменти між смугами
- Обмежену кількість ходів

**Два типи дій:**
1. **Обертання (Rotate)** — горизонтальне зміщення всіх сегментів у смузі. Один рух = один хід.
2. **Слайд (Slide)** — вертикальне переміщення стовпчика сегментів через слайд-арену. Один рух = один хід.

**Умова перемоги:** Всі сегменти в кожній смузі мають бути одного кольору (IsCompleted).

**Умова поразки:** Ходи вичерпані, але не всі смуги заповнені.

### 1.2 Існуючі ігрові механіки

| Механіка | Опис | Складність |
|----------|------|-----------|
| **Rotate** | Горизонтальне прокручування сегментів у смузі | Базова |
| **Slide** | Вертикальне переміщення між смугами через арени | Базова |
| **Blocked segments** | Сегменти, що не можуть бути переміщені (обмежують слайд) | Помірна |
| **FilterColors** | Арена дозволяє слайд лише певних кольорів | Помірна |
| **Empty segments (Pre-game)** | Пусті слоти, які гравець заповнює перед грою з пулу | Помірна |
| **Tutorial** | Базова система підказок (але `IsTutorialCompleted` завжди `false`) | Мінімальна |

### 1.3 Пул рівнів та обсяг контенту

- **newBalance:** 50 рівнів (з різною складністю)
- **GeneratedLevels:** 19 рівнів (згенеровані через A* солвер)
- **Загалом:** ~69 рівнів
- **Час проходження:** ~1-2 хвилини на рівень → **~70-140 хвилин** = **1.2-2.3 години**
- **Складність:** Визначається формулою `MovesForLevel = Difficulty × DifficultyMultiplier (2.0)`
- **Параметри, що варіюються:** Кількість смуг, кількість секторів, кількість арен, кількість кольорів (до 6), Blocked, FilterColors, Empty

### 1.4 Система прогресії

**Поточна прогресія:**
- Лінійна: Level 1 → Level 2 → Level 3 → ...
- `PlayerProgressData` зберігає лише поточний номер рівня (`int Level = 1`)
- Немає картки рівнів, глав, або візуальної прогресії
- Немає рейтингу (зірки, бали)
- Немає прив'язки до соціальних мереж

## ЧАСТИНА 2: ІГРОВИЙ ДИЗАЙН — АНАЛІЗ РИЗИКІВ

### 2.1 Ключові ризики для утримання (Retention)

**Ризик 1: "Механіка занадто швидко стає зрозумілою"**
- Гра має лише 2 типи дій (rotate + slide). Після 10-15 рівнів гравець повністю розуміє всі комбінації.
- **Наслідок:** D7 retention може бути низьким, якщо немає елементів, що ускладнюють/змінюють досвід.
- **Рекомендація:** Потрібні нові механіки або зміна правил з часом (unlock нових механік).

**Ризик 2: "Немає мети окрім 'пройти наступний рівень'"**
- Прогресія — просто номер рівня. Немає візуальної карти, зірок, досягнень.
- Гравець не бачить свого прогресу.
- **Наслідок:** Мотивація "відкрити наступне" слабка.

**Ризик 3: "Немає причин повертатися щодня"**
- Немає daily rewards, daily challenges, streaks.
- Гравець може пройти все за один сеанс і ніколи не повернутися.

**Ризик 4: "Поразка відчувається несправедливо"**
- Коли ходи закінчуються — просто LoseView. Немає хінтів, немає можливості відкрутити хід.
- +5 ходів без обмежень — занадто щедро, знецінює складність.

**Ризик 5: "Немає аналітики — не можна приймати рішення"**
- Без analytics не можна зрозуміти, на яких рівнях гравці застрягають, де кидають гру, які механіки працюють.

### 2.2 Порівняння з успішними puzzle games

| Метрика | Типовий бенчмарк | Color Rings зараз |
|---------|------------------|-------------------|
| D1 Retention | 40-55% | ❓ Невідомо (немає analytics) |
| D7 Retention | 15-25% | ❓ Невідомо |
| Avg Session Length | 5-15 хв | ~10-20 хв (оцінка) |
| Sessions per Day | 2-4 | ❓ Невідомо |
| Levels per Session | 3-8 | ~5-10 (оцінка) |
| Total Levels for Soft Launch | 100-300+ | ~69 ⚠️ Замало |
| Star Rating | Є (майже завжди) | ❌ Немає |
| Hint System | Є (майже завжди) | ❌ Немає |
| Daily Challenge | Є (у 60%+ puzzle games) | ❌ Немає |

## ЧАСТИНА 3: ПРОПОНОВАНІ ФІЧІ — АНАЛІЗ

### A) CORE FEATURES (Пов'язані з ігровим процесом)

---

#### A1. Star Rating System (1-3 зірки за рівень)

**Опис:** Кожен рівень оцінюється від 1 до 3 зірок. Наприклад:
- 3 зірки: менше ніж X% ходів від ліміту
- 2 зірки: менше ніж Y% ходів
- 1 зірка: просто пройти рівень

**Чому гравці будуть цінувати:** Дає мету "проходити ідеально". Перепроходження рівнів заради 3 зірок подовжує загальний час гри. Без зірок рівень або пройдений, або ні — немає градації.

**Мотивація:** Mastery (майстерність), Completionism (завершеність). Гравці з перфекціонізмом будуть грати заново.

**Частота в успішних puzzle games:** 90%+ (Candy Crush, Toon Blast, Homescapes, Royal Match — всі мають зірки)

**Складність реалізації:** Низька. Потрібно: formula для зірок, UI елементи, збереження.

**Вплив на retention:** 🔴 Дуже високий. Без зірок puzzle game виглядає незавершеною для видавців.

---

#### A2. Hint System (Підказки)

**Опис:** Гравець може отримати підказку, яка підсвічує оптимальний хід або автоматично виконує один хід.

**Варіанти реалізації:**
- **Highlight hint:** Підсвічує сегмент і напрямок руху
- **Auto-move hint:** Автоматично виконує один оптимальний хід (використовує A* solver)
- **Обмежена кількість:** 3-5 безкоштовних на день, потім — за монети/перегляд реклами

**Чому гравці будуть цінувати:** Запобігає фрустрації. Коли гравець "застряг" і не бачить рішення — хінт рятує сеанс.

**Мотивація:** Страх втрати прогресу + бажання просуватися далі.

**Частота в успішних puzzle games:** 95%+ (мають практично всі)

**Складність реалізації:** Середня. Солвер вже є (A*) — потрібно інтегрувати як хінт.

**Вплив на retention:** 🔴 Дуже високий. Запобігає "quit forever" після застрягання.

---

#### A3. Undo Move (Скасування ходу)

**Опис:** Гравець може відмінити останній хід (1-3 рази на рівень безкоштовно).

**Чому гравці будуть цінувати:** Знижує фрустрацію від помилкових ходів. Дозволяє експериментувати без страху.

**Мотивація:** Контроль + безпека. Гравець боїться робити ходи, якщо не може відмінити.

**Частота в успішних puzzle games:** 70%+ (Toon Blast, Royal Match, Homescapes)

**Складність реалізації:** Помірна. Потрібно зберігати стан до кожного ходу.

**Вплив на retention:** 🟡 Середній. Знижує точку входу, але не є критичним.

---

#### A4. New Puzzle Mechanic — "Color Filter" (Розблоковується на рівні 10+)

**Опис:** Нова механіка, яка розблоковується після перших 10-15 рівнів. Наприклад:
- **Color Filter segments:** Сегменти, які змінюють колір проходятього через них сегмента (наприклад, червоний + фільтр = помаранчевий)
- **One-way arrows:** Арени, де слайд можна робити тільки в один бік

**Чому гравці будуть цінувати:** Оновлює досвід, створює відчуття "гра стає складнішою".

**Мотивація:** Curiosity (цікавість) + Mastery (вивчення нових правил).

**Частота в успішних puzzle games:** 80%+ (більшість successful puzzle games додають нові механіки з часом)

**Складність реалізації:** Висока. Потрібно: нові статуси сегментів, нова логіка solver, UI/visual.

**Вплив на retention:** 🔴 Високий. Забезпечує D7+ retention через новизну.

---

#### A5. Difficulty Curve Tuning (Налаштування кривої складності)

**Опис:** Поточна крива складності не оптимізована для retention. Потрібно:
- Рівні 1-5: Дуже легкі (tutorial-like, 2-3 ходи)
- Рівні 6-15: Легкі-середні (5-8 ходів, базові механіки)
- Рівні 16-30: Середні (8-12 ходів, Blocked + FilterColors)
- Рівні 31-50: Середньо-складні (10-15 ходів, Empty segments)
- Рівні 51+: Складні (15+ ходів, всі механіки)

**Чому гравці будуть цінувати:** Рівень складності відповідає навичкам гравця. Занадто складні рівні рано = frustration. Занадто легкі = boredom.

**Частота в успішних puzzle games:** 100% (всі мають криву складності)

**Складність реалізації:** Низька-середня. Level generator вже підтримує target difficulty.

**Вплив на retention:** 🔴 Критичний. Неправильна крива = втрата гравців.

---

#### A6. Level Pool Expansion (Розширення пулу рівнів)

**Опис:** Потрібно мінімум 150-200 рівнів для soft launch. Зараз ~69.

**Поточний дефіцит:** ~80-130 рівнів.

**Стратегія:** Використати існуючий генератор для створення 100+ нових рівнів з правильними параметрами складності.

**Складність реалізації:** Низька (генератор вже є, потрібно налаштувати параметри).

**Вплив на retention:** 🔴 Критичний. 69 рівнів — замало для 2+ тижнів гри.

### B) META FEATURES (Навколо ігрового процесу)

---

#### B1. Analytics System (Система аналітики)

**Опис:** Трекінг ключових подій:
- Level started / completed / failed
- Moves used per level
- Time spent per level
- Hint usage
- Session length / frequency
- Where player quit (який рівень останній)
- Feature engagement (які механіки використовуються)

**Події для трекінгу:**
```
level_start {level_id, attempt_number}
level_complete {level_id, moves_used, time_seconds, stars_earned}
level_fail {level_id, moves_used, time_seconds}
hint_used {level_id, hint_type}
session_start / session_end
purchase (якщо буде IAP)
```

**Чому важливо:** Без analytics ви летите наосліп. Видавці вимагають дані.

**Складність реалізації:** Середня. Firebase Analytics або AppsFlyer.

**Вплив:** 🔴 Критичний для прийняття рішень.

---

#### B2. Progress Map / Level Select (Карта прогресію)

**Опис:** Візуальна карта з номерами рівнів, зірками, та блокуванням ( Locked → Next → Completed with stars).

**Чому гравці будуть цінувати:** Бачать свій прогрес, мають ціль "дістатися до кінця".

**Частота в успішних puzzle games:** 85%+ (Candy Crush map, Toon Blast map)

**Складність реалізації:** Середня. Потрібен UI з скролінгом.

**Вплив на retention:** 🔴 Високий. Дає зорову мету.

---

#### B3. Daily Challenge (Щоденний виклик)

**Опис:** Один унікальний рівень на день для всіх гравців. Нагорода за проходження.

**Чому гравці будуть цінувати:** Повертає гравця щодня. Конкуренція з іншими гравцями.

**Мотивація:** Routine (звичка) + Social comparison.

**Частота в успішних puzzle games:** 60%+ (Candy Crush Saga, Royal Match)

**Складність реалізації:** Помірна. Потрібен серверний компонент або seed-based генерація.

**Вплив на retention:** 🔴 Високий для D7.

---

#### B4. Hint Economy / Stars Economy (Економіка підказок)

**Опис:** Гравець заробляє "хінти" або "монети" за:
- Завершення рівня (1-3 за зірки)
- Щоденний бонус
- Перегляд реклами (опціонально)
- IAP (опціонально)

Витрачає на:
- Підказки (highlight/auto-move)
- Додаткові ходи
- Undo

**Чому важливо:** Створює економічний цикл, який мотивує повертатися.

**Частота в успішних puzzle games:** 90%+

**Складність реалізації:** Помірна.

**Вплив на retention:** 🟡 Середній-високий.

---

#### B5. Streak System (Система серій)

**Опис:** Гравець отримує бонуси за щоденне входження:
- День 1: 1 хінт
- День 2: 2 хінти
- День 3: 3 хінти + bonus moves
- День 7: special reward

**Чому гравці будуть цінувати:** Страх втратити серію мотивує повертатися щодня.

**Мотивація:** Loss aversion (страх втрати) + Routine.

**Частота в успішних puzzle games:** 70%+

**Складність реалізації:** Низька.

**Вплив на retention:** 🔴 Високий для D7.

---

#### B6. Failure Recovery (Система відновлення після поразки)

**Опис:** Поточна система: LoseView → +5 ходів (без обмежень) / Restart / MainMenu.

**Проблеми:**
- +5 ходів без обмежень → знецінює складність
- Немає стимулу дивитися рекламу за ходи
- Немає "бонусного" рівня для заробітку ресурсів

**Покращена версія:**
- +5 ходів за перегляд реклами (1 раз на рівень)
- +3 ходи безкоштовно (1 раз на рівень)
- Restart безкоштовно
- "Bonus level" для заробітку хінтів (опціонально)

**Частота в успішних puzzle games:** 90%+

**Складність реалізації:** Низька-середня.

**Вплив на retention:** 🟡 Середній.

---

#### B7. Achievement System (Система досягнень)

**Опис:** Досягнення за:
- "Перший рівень" / "10 рівнів" / "50 рівнів"
- "Всі зірки" на рівні / на главі
- "100 ходів" / "1000 ходів"
- "5 днів поспіль"

**Чому гравці будуть цінувати:** Додаткові цілі окрім основної прогресії.

**Частота в успішних puzzle games:** 50%+

**Складність реалізації:** Низька.

**Вплив на retention:** 🟢 Низький-середній.

## ЧАСТИНА 7: РИЗИКИ ТА ОБМЕЖЕННЯ

### Ризики:

1. **Level generator може генерувати нерозв'язні рівні** — потрібна валідація solver перед релізом
2. **BinaryFormatter міграція** — може зламати save існуючих гравців (якщо є бета-тестери)
3. **Tutorial система недопрацьована** — `IsTutorialCompleted` завжди false, потрібно виправити
4. **Pre-game placement може бути незрозумілим** — гравець може не зрозуміти, що потрібно робити
5. **Одноманітність візуалу** — всі рівні виглядають однаково (горизонтальні смуги). Потрібні теми/скіни.

### Обмеження:

- Поточний save system (BinaryFormatter) не працює на IL2CPP/WebGL — потрібна міграція
- Tutorial не працює — гравець може не зрозуміти механіки
- Debug панель доступна — може бути випадково відкрита
